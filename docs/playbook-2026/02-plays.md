## 4장. 스마트 조달 5단계 프레임워크

```
 ① 가시화 ──▶ ② 표준화 ──▶ ③ 경쟁화 ──▶ ④ 자동화 ──▶ ⑤ 지능화
 (모으기)     (맞추기)     (비교하기)    (줄이기)     (예측하기)
 발주 요청    품목코드     복수견적      발주 초안     수요 예측
 단일 창구    표준 양식    역경매        3-way 대사    단가 예측
 이력 축적    전결 규정    공급사 점수   자동 알림     최적 발주
```

| 단계 | 목표 | 대표 산출물 | 완료 기준 |
|------|------|-----------|----------|
| ① 가시화 | 흩어진 발주를 한 곳으로 | 발주 요청 단일 창구, 거래 이력 DB | 파일럿 현장 발주의 90% 이상이 플랫폼 경유 |
| ② 표준화 | 같은 것을 같은 이름으로 | 품목 마스터, 표준 발주 양식, 전결 규정 | 주요 품목 코드 매핑률 95% 이상 |
| ③ 경쟁화 | 모든 구매를 비교 가능하게 | 복수 견적, 역경매, Supplier Trust Score | 평균 응찰 공급사 3개 이상 |
| ④ 자동화 | 반복 업무를 시스템이 | 발주 초안, 3-way 대사, 납기 알림 | 발주 처리 시간 50% 이상 단축 |
| ⑤ 지능화 | 데이터로 미리 판단 | 단가 검증·이상 탐지·수요 예측 AI | AI 권고 수용률·절감액 정기 리포트 |

> 원칙: **단계를 건너뛰지 않는다.** 품목 표준화(②) 없이 AI 단가 검증(⑤)을 하면 비교 대상이 맞지 않아 오탐이 급증합니다.

## 5장. 프로세스별 실행 플레이

조달 흐름: **소요계획 → 견적·소싱 → 단가 검증 → 입찰·역경매 → 발주 → 납품·검수 → 정산·금융 → 잉여자재**

### 플레이 1. 소요 계획 & 물량 산출

| 항목 | 내용 |
|------|------|
| **목표** | 공정표 기반으로 자재 소요를 미리 확정해 긴급 발주를 줄인다 |
| **As-Is** | 공정 직전 전화 수배, 물량은 담당자 경험·수작업 산출 |
| **To-Be** | 도면 기반 AI 물량 산출 → 공정표와 연결된 발주 계획 → 리드타임 역산 알림 |
| **AI 역할** | 도면에서 물량 자동 산출(Beta), 품목별 리드타임 기반 "발주 마감일" 계산 |
| **KPI** | 긴급 발주 비율, 물량 산출 소요 시간, 계획 대비 실발주 편차율 |

**실행 단계**
1. 파일럿 공종 1개 선정(예: 철근·레미콘처럼 물량이 크고 반복적인 공종)
2. 공정표의 주요 마일스톤을 플랫폼에 등록
3. AI 물량 산출 결과를 담당자가 검토·보정(초기엔 반드시 사람이 확인)
4. 품목별 리드타임을 등록해 발주 마감일 알림 설정
5. 월말에 "계획 vs 실발주" 편차를 리뷰하고 산출 기준 보정

**체크리스트**
- [ ] 물량 산출 결과에 산출 근거(도면·층·부위)가 남는가
- [ ] AI 산출치와 담당자 보정치의 차이를 기록하는가(모델 개선용)
- [ ] 리드타임 정보가 공급사별로 최신인가

---

### 플레이 2. 견적 요청 & 공급사 탐색

| 항목 | 내용 |
|------|------|
| **목표** | 모든 주요 구매에 3~5개 공급사 견적을 빠르게 확보 |
| **As-Is** | 아는 업체 1~2곳에 전화, 견적서는 팩스·사진 |
| **To-Be** | 품목·수량·납기 입력 → AI가 공급사 추천 → 일괄 견적 요청 → 표준 양식으로 비교 |
| **AI 역할** | **공급사 추천 에이전트**(6.2절): 품목 적합도·지역·Trust Score·응답률 기반 순위 |
| **KPI** | 평균 견적 수, 견적 회신 시간, 신규 공급사 발굴 수 |

**실행 단계**
1. 기존 거래 공급사 리스트 업로드 → 일괄 초대(48시간 내 온보딩 목표)
2. 견적 요청 양식 표준화: 품목코드, 규격, 수량, 납기, 납품지, 운반 조건, 결제 조건
3. 추천 공급사 + 기존 거래처를 혼합해 요청(기존 관계 유지 + 경쟁 도입)
4. 회신 마감 시간 설정, 미회신 공급사 자동 리마인드
5. 견적을 **동일 조건(운반비·부가세·결제조건 포함 총액)** 으로 정규화해 비교

**체크리스트**
- [ ] 견적 비교가 "단가"가 아닌 "총 도착가(Landed Cost)" 기준인가
- [ ] 특정 공급사만 반복 초대되고 있지 않은가(7장 룰 R6)
- [ ] 공급사가 등록 서류(사업자등록·통장사본·면허 등)를 갖췄는가

---

### 플레이 3. 단가 검증

| 항목 | 내용 |
|------|------|
| **목표** | 모든 견적·발주 단가를 데이터로 자동 검증해 과다 지불 방지 |
| **As-Is** | 담당자 감, 또는 공시 단가(물가정보지 등) 수동 대조 |
| **To-Be** | 견적 접수 즉시 실거래 시세(GPI)·과거 이력·동일 시기 타 현장 단가와 자동 비교, 편차 등급 표시 |
| **AI 역할** | **단가 검증 에이전트**(6.3절): 기준 단가 산출, 편차 등급(정상/주의/경고), 근거 제시 |
| **KPI** | 검증 커버리지(검증된 발주 금액 비율), 경고 건 재협상 성공률, 단가 절감액 |

**실행 단계**
1. 기준 단가 소스 우선순위 정의: ① 플랫폼 실거래(GPI) ② 자사 과거 거래 ③ 공시 단가
2. 품목별 허용 편차 기준을 **설정값으로** 정의(품목군별 가격 변동성 반영)
3. "경고" 등급은 승인 전 사유 입력 필수로 워크플로우 설정
4. 월 1회 품목별 단가 추이 리포트로 단가 계약 갱신 근거 확보

**체크리스트**
- [ ] 비교 대상의 규격·수량 구간·지역·시점이 일치하는가
- [ ] 원자재 급등기에 과거 단가만으로 판단하지 않도록 시세 반영 주기가 짧은가
- [ ] 검증 결과(기준가·편차·근거)가 발주 기록에 함께 저장되는가

### 플레이 4. 입찰 & 역경매

| 항목 | 내용 |
|------|------|
| **목표** | 경쟁을 통해 시장가를 발견하고 구매 단가 인하 |
| **As-Is** | 수의계약 위주, 입찰은 서면·이메일 |
| **To-Be** | 전자입찰(밀봉) 또는 역경매(실시간 하향) 선택, 결과 자동 기록 |
| **AI 역할** | 입찰 방식 추천(품목 표준화 정도·공급사 수 기준), 담합 의심 패턴 탐지(7장 R4) |
| **KPI** | 평균 입찰 경쟁률, 예정가 대비 낙찰가율, 유찰률 |

**방식 선택 가이드**

| 상황 | 권장 방식 |
|------|----------|
| 규격이 표준화된 범용 자재, 공급사 다수 | 역경매 |
| 사양·품질 평가가 중요한 자재·장비 | 밀봉 입찰 + 기술·가격 종합 평가 |
| 반복 구매, 연간 물량 예측 가능 | 단가 계약(연간/분기) 입찰 |
| 긴급 소량 | 간이 견적 비교(플레이 2) |

**체크리스트**
- [ ] 입찰 조건(납기·품질·결제)이 모든 응찰자에게 동일하게 공지됐는가
- [ ] 최저가만이 아니라 Trust Score를 함께 평가하는가
- [ ] 낙찰 사유가 기록되는가(최저가 아닌 업체 선정 시 필수)

### 플레이 5. 발주 자동화

| 항목 | 내용 |
|------|------|
| **목표** | 발주서 작성·승인·전달을 자동화해 처리 시간 단축과 오류 제거 |
| **As-Is** | 엑셀 발주서 작성 → 출력·결재 → 팩스·전화 전달 |
| **To-Be** | 낙찰/선정 결과로 발주서 자동 생성 → 전결 규정에 따른 전자 승인 → 공급사 자동 전달 → ERP 구매전표 생성 |
| **AI 역할** | **발주 자동화 에이전트**(6.5절): 발주 초안 생성, 누락 필드 검사, 승인 경로 결정 |
| **KPI** | 발주 처리 리드타임, 발주 오류(정정·취소) 건수, 전자 발주 비율 |

**실행 단계**
1. 전결 규정(금액·품목·현장별 승인권자)을 시스템 설정으로 등록
2. 반복 품목은 단가 계약 기반 "원클릭 재발주" 활성화
3. 발주 전달 후 공급사 "수주 확인" 응답 의무화, 미응답 시 알림
4. ERP 연동 시 발주 → 구매전표 자동 생성(11장 연동 참고)

**체크리스트**
- [ ] AI가 만든 초안은 **반드시 사람이 승인**한 뒤 발송되는가
- [ ] 승인 한도 직하 금액 발주가 반복되지 않는가(7장 R1 쪼개기)
- [ ] 발주 변경·취소 이력이 원본과 함께 보존되는가

### 플레이 6. 납품 & 검수

| 항목 | 내용 |
|------|------|
| **목표** | 납품 수량·규격·품질을 현장에서 즉시 디지털로 확인 |
| **As-Is** | 종이 송장, 구두 확인, 사후 수기 입력 |
| **To-Be** | 모바일 검수(사진·수량·규격), 발주 대비 차이 자동 표시, 하자 클레임 즉시 등록 |
| **AI 역할** | 발주-납품 차이 탐지, 납기 지연 공급사 Trust Score 반영 |
| **KPI** | 납기 준수율, 검수 불일치율, 품질 클레임 건수 |

**체크리스트**
- [ ] 검수자와 발주자가 분리돼 있는가(직무 분리)
- [ ] 검수 사진·시간·위치가 기록되는가
- [ ] 부분 납품·분할 납품이 수량 기준으로 추적되는가

### 플레이 7. 정산 & 조달 금융

| 항목 | 내용 |
|------|------|
| **목표** | 정산 오류를 없애고 공급사 현금흐름을 개선해 단가 인하 여력 확보 |
| **As-Is** | 세금계산서 수작업 대사, 지급까지 60~120일 |
| **To-Be** | 발주-검수-세금계산서 **3-way 자동 대사**, 공급사 조기 결제 옵션(KODIT 연계 금융, 파일럿 예정) |
| **AI 역할** | 대사 불일치 자동 탐지, 중복 청구 탐지(7장 R8) |
| **KPI** | 자동 대사율, 정산 리드타임, 조기 결제 이용률 |

**체크리스트**
- [ ] 검수 완료 전 정산이 불가능하도록 막혀 있는가
- [ ] 동일 공급사·금액·일자 중복 청구를 차단하는가
- [ ] 하도급 대금 지급 기일 관련 법규 준수 여부를 모니터링하는가(12장)

### 플레이 8. 잉여자재 순환 (무료 진입점)

| 항목 | 내용 |
|------|------|
| **목표** | 남은 자재를 비용이 아닌 수익으로 바꾸고, 플랫폼 첫 경험을 만든다 |
| **As-Is** | 폐기 비용 부담 또는 헐값 처분 |
| **To-Be** | 잉여자재 등록(사진·수량) → 인근 현장·시공사 역경매 → 낙찰·인계 |
| **AI 역할** | 사진 기반 품목 분류, 적정 처분가 제안, 인근 수요 현장 매칭 |
| **KPI** | 월 역경매 거래 건수, 처분 회수율(장부가 대비), 등록→낙찰 소요 시간 |

> 💡 **도입 전략:** 잉여자재 역경매와 긴급 견적 비교는 무료로 제공해 현장소장이 비용 부담 없이 효과를 체감하게 합니다. "현장에서 편하다"는 경험이 본사 도입 결정으로 이어지는 Bottom-Up 경로입니다.
